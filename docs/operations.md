# 运维手册

## 日常检查

- `/health`：进程与平台模式。
- `/api/v1/stats`：事件、预警、国家、旅客和数据源状态。
- `/api/v1/admin/stats/overview?hours=24`：任务成功率、传输量、API 平均/P95、错误与操作量。
- 互联网“数据源管理”：最近运行、错误、周期、URL、启停及手动采集。
- 内网“数据接收中心”：接收包、验签失败、目录/队列/API 通道。

应用日志位于 `runtime/logs/<platform>.jsonl`，按日轮转并保留 180 份；数据库审计日志没有删除 API。仅审计员可查询和导出审计日志，系统管理员不能查看，以满足职责分离。

## 备份与恢复

生产每天 02:00 自动全量备份，保留 14 天；02:30 清理过期备份。每个备份包括：

- `.dump` 或 `.sqlite3`：数据库、规则、用户和业务数据。
- `.assets.tar.gz`：原始数据、摆渡资源、内网旅客加密归档及不含秘密的配置清单。

PostgreSQL 开启 WAL 归档，`archive_timeout=900s`。管理界面可手动备份和恢复；恢复必须输入备份编号，服务先校验 SHA-256，SQLite 还会生成 `pre_restore_*.sqlite3` 快照。生产 PostgreSQL 恢复前应先停止写入、创建当前快照，完成后执行健康检查和抽样核对。

演练流程：手动备份 → 记录事件/规则/用户数量 → 在隔离演练环境恢复 → 核对数量与校验和 → 登录和接口抽测 → 记录 RTO/RPO。至少每季度执行一次。

## 采集故障

1. 查看数据源最近错误和 `source_runs`。
2. 确认 URL、DNS、证书和对方限流政策。
3. 在页面单独触发该源；适配器会指数退避重试。
4. 不要删除原始文件；SHA-256 指纹可证明原始输入并防止重复落盘。

## 信息源、计划与模型故障

信息源的地址、解析模式、固定间隔/Cron、时区、模型和提示词都从数据库读取。修改保存后检查页面返回的“下次运行”；Cron 时间异常时先核对所选 IANA 时区和服务器时钟。单一来源失败不会中止其他来源，使用 `source_runs` 定位该源的下载、解析或模型错误。

模型连接异常时依次检查：供应商是否启用、服务地址、密钥是否已保存、获取到的模型名称、TLS/域名和本安全域的出站策略；然后在“大语言模型”页执行连接测试。连接测试会发送最小对话并记录状态与延迟，但不会显示密钥。删除供应商前必须先将引用它的信息源切回内置解析或改用其他供应商。

内网未配置供应商时，事件研判返回 409 且不会外联，这是预期安全状态。物理隔离环境不得为了连接云模型临时增加公网默认路由，应部署域内模型服务并留存变更审批记录。

## 摆渡故障

- 文件失败包进入 `inbound/rejected`，先核对两侧算法和密钥职责，再重试新任务。
- 签名或校验失败不得人工绕过。
- RabbitMQ 检查持久队列、单向代理和死信；消费失败不会确认消息。
- API 轮询只允许配置地址，不接受请求参数中的任意 URL，避免 SSRF。
- `package_id` 已导入时返回 `duplicate`，不重复写业务表。

## 旅客文件接口

监控目录由 `PASSENGER_INBOUND_ROOTS` 逗号分隔配置，文件名使用 `PASSENGER_日期_序号.csv|jsonl`。每 10 秒扫描；成功和失败原文件都会用字段密钥转为 `.enc` 归档，明文源文件被消费，审计日志不记录旅客内容。

## 密钥轮换

JWT 和字段密钥轮换需安排维护窗口；字段密钥变化前必须完成数据重加密。摆渡密钥轮换采用版本化双钥过渡：先向接收端部署新验签/解密键，再切发送端，确认旧包清空后撤旧键。密钥不得进入工单正文、日志或普通备份。
