# 安全设计与等保三级基线

本实现覆盖等保三级常见技术控制，但正式“等保三级”结论仍必须由有资质机构按实际机房、网络、制度和人员流程测评，软件不能自行宣称通过认证。

## 已实现控制

- 身份鉴别：bcrypt 独立盐、复杂度、5 次锁定 15 分钟、TOTP、内网管理员强制 MFA、LDAP/AD 与本地故障账号并存。
- 访问控制：五角色最小权限；审计员与管理员职责分离；互联网/内网 JWT audience 隔离；路由与构建产物隔离。
- 数据保护：旅客证件、姓名、联系方式 AES-256-GCM 字段加密；证件盲索引；页面脱敏；日志不记录请求体。
- 边界：内网 Docker 网络 internal；前端 CSP `connect-src 'self'`；离线产物不引用 CDN；API 轮询默认关闭且地址只能来自启动配置。
- 传输：TLS 由区内网关终止；摆渡包认证加密、独立签名、SHA-256、源目标约束、Schema 校验和 package ID 幂等。
- 审计：写操作数据库留痕、API 性能表、JSONL 应用访问日志、请求 ID、安全响应头；无审计删除 API。
- 可用性：PostgreSQL WAL、每日完整备份、14 日保留、校验恢复、Redis 故障降级到进程缓存。

## 模型服务与信息源安全

- 两侧模型配置和 API 密钥独立落库，使用各自 `FIELD_ENCRYPTION_KEY` 进行认证加密；API、日志、备份资源清单和摆渡数据不回传或传输明文密钥。
- 供应商地址只接受无账号、查询参数和片段的 HTTP(S) URL，并禁止云元数据地址；连接不跟随重定向。内网默认没有供应商，也不会自行外联，管理员显式配置的地址应纳入防火墙白名单和变更审计。
- 模型输出属于辅助研判，不替代来源事实。事件提示词要求区分事实和建议；信息提取限制输入/输出规模、丢弃未知国家记录，并保留原始采集文件以供核验。
- 信息源、周期、时区、解析模型和提示词是受 RBAC 保护的用户配置。预设只在空库首次导入，运行期不会用代码常量覆盖用户配置。

## 上线前组织与环境项

1. 完成资产定级、备案、差距评估、渗透测试、漏洞扫描和第三方测评。
2. 在两个安全域分别部署 WAF/反向代理、堡垒机、主机防护、集中日志和时间同步。
3. 使用企业 KMS/HSM 托管密钥；容器只接收短期挂载或秘密注入。
4. 配置 TLS 1.2+、mTLS、证书吊销、IP 白名单和网闸厂商策略。
5. 建立账号审批、季度复核、离职回收、备份演练、事件响应和介质管理制度。
6. 对 LDAP 服务账号授予只读搜索权限，使用 LDAPS，限制内网 API 主机来源。
7. 对采集数据遵守来源条款、robots/频率政策和个人信息最小化原则。
